## Internationalization Rules (@nuxtjs/i18n)

- **Strict i18n usage:** All user-facing strings must use `$t('key')` or `useI18n()` composable. No hardcoded text.
- **No hardcoded strings in stores or repositories:** Stores and repositories have no i18n context and must never contain user-facing display strings. Expose boolean error flags (e.g. `isError: boolean`) and let the component/page layer handle copy via `$t()`.
- **Components:** Components must use the `$t` function within `<template>`.
- **Pages/Routes:** All route links must use `localePath()` to ensure correct prefixing (e.g., `<NuxtLink :to="localePath('about')">`).
- **Translation Files:** Define translations in `i18n/locales/*.json`.
- **Best Practice:** Always use nested keys (e.g., `feature.action.key`) for better organization.
- **Pluralization:** Use ICU message format for pluralization in JSON files.
- **Switching Language:** Use `switchLocalePath()` to change languages.
